# PaperFate 사용 가이드

> 투고 전 단계의 임상/생의학 원고를 위한 사전 예측 도구입니다.
> 이 문서는 PaperFate가 지금 무엇을 해 주는지, 어떻게 쓰는지,
> 그리고 결과를 어디까지 믿어도 되는지를 정리합니다.
> 한국어 화면에서 바로 보이는 표현을 따라 썼고, 영문 가이드의 직역이
> 아닙니다.

---

## 1. PaperFate가 하는 일

원고 초안(최소한 제목 + 초록, 필요하면 Methods/Results/Discussion,
저자, 참고문헌, 목표 저널까지)을 받아서 다음을 돌려줍니다.

- 도달 가능성이 높은 저널의 Impact Factor 예측값과 90% 신뢰구간
- 현실적인 투고 경로(Journey) 5단계
- Q-루브릭 도메인별 점수와 약점, 그리고 점수를 끌어올릴 수 있는
  구체적 제안
- 비슷한 발표 논문 후보(OpenAlex 검색)

판결이 아니라 의사결정 보조 도구입니다. 본인과 공저자의 판단을
대체하려고 만든 게 아니라, 그 옆에 둘 수 있게 만든 것입니다.

---

## 2. 원고 입력하기

홈 화면에서 **Simulator** 영역을 엽니다.

### 최소 입력

두 가지만 있으면 예측이 돌아갑니다.

- **제목** — 9자 이상
- **초록** — *Abstract* 탭에서 200자 이상,
  *Full text* 탭에서는 본문 1,000자 이상

이것만 있어도 서버가 연구 유형, 분야, 적용 루브릭을 자동으로 잡습니다.

### 있으면 더 좋아지는 입력

이 항목들은 예측 실행 여부에는 영향을 주지 않습니다. 다만 결과의
해상도를 올려 줍니다.

- **Field / Study type** — 초록이 애매하지 않다면 *Auto-detect*로
  두세요. 강제 지정이 필요할 때만 골라 주면 됩니다.
- **Target tier** — 특정 IF 구간을 노리는 경우에만 변경합니다.
- **Authors** — 표지에 실릴 저자 byline을 그대로 붙여 넣으세요.
  OpenAlex로 이름을 매칭해서 h-index 벡터를 만듭니다. 한 번에 최대
  25명까지.
- **References** — DOI를 줄바꿈이나 콤마로 구분해 붙여 넣으세요.
  최대 50개까지 OpenAlex로 해소되고, 각 저널의 JIF를 join해서
  참고문헌의 평균/중앙 JIF, 주요 저널, 발행 연도 중앙값을
  보여줍니다. 초록만으로는 빈약할 때 예측을 안정화시키는 핵심
  앵커입니다.
- **Target journal** — 저널 이름을 치면 JIF, OA 여부, APC, h-index,
  분기 정보가 따라오고, 결과 패널에서 본인 예측이 그 저널과 얼마나
  벌어져 있는지를 비교해 줍니다.

### 샘플 원고

Simulator에는 RCT, 메타분석, 코호트, 의료 AI 영상 등 4가지 샘플이
들어 있습니다. 자기 원고를 붙이기 전에 한 번 눌러서 UI 흐름을
체감해 보세요.

### 단축키

- **Ctrl/Cmd + Enter** — 어느 텍스트 박스에서든 폼 제출.

### 두 가지 실행 모드

- **Abstract 모드** — 제목 + 초록만으로 Q500 예측을 돌립니다.
- **Full text 모드** — Methods, Results, Discussion 같은 구조화된
  본문이나 긴 단일 본문을 받습니다. 초록만으로는 채점할 수 없는
  방법론 디테일 항목까지 루브릭이 확장됩니다.

Full text 모드에서 본문이 너무 짧으면(methods + results + discussion
+ full text 합쳐서 1,500자 미만), 자동으로 Q100 short-body 경로로
빠집니다. 결과 응답에 `auto_decision: Q100_short_body`로 표시됩니다.

## 3. 결과 패널 읽기

예측이 끝나면 결과 패널로 자동 스크롤됩니다. 위에서 아래로 살펴봅니다.

### Forecast for "…"
입력한 제목(화면에서는 90자까지 표시). 아래 작은 띠에 검출된 저자
수, 해소된 참고문헌 DOI 수, 사용된 모드(Q100/Q500)가 뜹니다.

저자를 5명 입력했는데 OpenAlex 매칭이 0이면 호박색(amber) 칩으로
이름이 잘못된 포맷일 수 있다고 경고합니다(예: 콤마 없이 성 먼저).
이 경우 이름을 정돈하고 다시 돌리면 h-index 집계가 또렷해집니다.

### ScoreDial
Q-루브릭 도메인 평균을 굴려 만든 0~5점 종합 점수입니다.

### 예상 저널 등급(Expected journal tier)
카드 3개로 구성됩니다.

- **Expected JIF (점추정값)** + 아래의 **90% 신뢰구간**. 목표
  저널을 입력해 두면 *Adjusted* 배지가 붙고, 앵커가 원 모델 값을
  얼마만큼 끌어당겼는지 delta가 표시됩니다.
- **Desk-reject 위험** — 확률값이지 판정문이 아닙니다.
- **리뷰 타임라인** — 투고~첫 결정까지의 일수 중앙값(모델 추정,
  소형 저널일수록 구간이 넓습니다).

### Journey
도전 가능한 저널부터 현실적인 백업까지 5단계로 정렬된 투고 후보
리스트입니다. 각 줄에 저널명, tier, JIF, 짧은 근거가 나옵니다.
가장 많이 보게 되는 영역인데, 그대로 순서대로 따르라는 뜻이
아니라 **shortlist의 시드**로 쓰세요.

### Adjusted JIF blend
목표 저널을 입력하면 모델의 **raw 예측**과, 목표 저널 정보로
앵커링된 **adjusted 예측**이 함께 표시됩니다. 신뢰도와 두 값의
거리에 따라 가중되어 섞입니다. 본인이 목표로 잡은 저널이 모델이
보는 현재 원고 수준에서 얼마나 떨어져 있는지를 직관적으로
확인할 수 있는 카드입니다.

### Domain rollup
Q-루브릭 도메인(Novelty, Design, Statistics, Reporting, Writing 등)
각각의 0~5 점수와 가장 약한 항목을 뽑아 보여줍니다. 도메인을
펼치면 어떤 루브릭 항목이 점수를 끌어내렸는지 항목 단위로 확인할
수 있습니다.

### Key weaknesses + suggestions
패널 안에서 신호 대 노이즈 비가 가장 좋은 영역입니다. 낮은 점수가
나온 루브릭 질문, 모델의 근거, 그리고 점수를 끌어올릴 수 있는
구체적 제안이 함께 나옵니다. 맨 아래 joint counterfactual은 약점
여러 개를 동시에 보완했을 때의 예상 lift를 보여줍니다.

> 룰 기반 폴백으로 실행된 경우에는 항목별 제안이 숨겨집니다.
> 룰 채점만으로 항목 단위 리라이트 제안을 내보내기에는 신뢰도가
> 부족하기 때문입니다.

### Similar papers
OpenAlex에서 제목·초록 검색으로 끌어온 발표 논문 최대 5편.
"이 원고와 가장 가까운 발표 논문이 어느 저널에 있는가"를 확인해
journey의 현실성을 교차 검증하는 용도로 쓰세요.

### References summary
DOI를 입력한 경우 해소 건수, 참고문헌 평균/중앙 JIF, 주요 저널,
주요 카테고리, 발행 연도 중앙값을 보여줍니다. 참고문헌이 얕거나
오래되었을 때 상위 저널이 안 받는 가장 흔한 이유 중 하나여서,
여기서 한눈에 잡힙니다.

## 4. 호박색(amber) "degraded mode" 배너

결과 패널 상단에 호박색 띠가 떴다면 —

> *LLM 채점이 현재 불가하여 룰 기반 예측만 표시합니다.
> Q-루브릭 도메인 점수는 제한되며, 잠시 후 다시 시도해 주세요.*

— LLM 채점 레이어가 실패해서(외부 LLM 장애, 키 만료, rate-limit 등)
서버가 결정론적 룰 기반 폴백을 반환한 상태라는 뜻입니다.

### 여전히 믿어도 되는 것

- **Journey**, **Similar papers** — LLM 채점과 무관합니다.
- **References summary**, **Author features** — OpenAlex join만으로
  계산됩니다.
- 거친 **tier 신호**(Q1 / Q2 / Q3 / Q4) — 룰 prepass도 정보량이
  0은 아닙니다.

### 믿으면 안 되는 것

- **항목별 루브릭 점수** — 상당수가 휴리스틱 추정입니다.
- **JIF 점추정값** — confidence가 0.30 이하로 캡되는 이유가 있습니다.
  "이 숫자다"가 아니라 "구간이 넓다" 정도로 해석하세요.
- **항목별 리라이트 제안** — degraded 모드에서는 숨겨집니다.

### 어떻게 해야 하나

몇 분 뒤 재시도하세요. 대부분 일시적인 외부 LLM 끊김이나 rate-limit
구간입니다. 푸터의 **Status** 페이지에서 전체 경로가 살아 있는지
먼저 확인하고 다시 돌리는 걸 권합니다.

## 5. Compare 탭 — 저널 비교

**Compare** 탭에 저널 이름이나 ISSN을 최대 5개까지 넣으면 한 화면에
나란히 보여줍니다: 이름, 출판사, JIF, JCR 분기, OA 여부, APC(USD),
h-index, scope. 한 번의 API 호출(`/api/journal-compare`)로 처리되어
네트워크가 느려도 빠릅니다.

이런 상황에서 쓰세요.

- 이미 후보 저널을 좁혔고, 정량 정보를 한 표에서 보고 싶을 때.
- 비슷한 tier의 OA 저널 vs. 구독형 저널을 고를 때(APC 비교).
- 도전 tier 한 곳과 현실 tier(예: Q2) 한 곳을 cover letter 쓰기 전
  같이 띄워 두고 싶을 때.

입력 내용은 10분 동안 localStorage에 보관되므로, 탭을 새로고침해도
반쯤 적은 후보가 살아 있습니다.

## 6. Quick rubric check — 빠른 루브릭 점검

Simulator의 **Quick rubric check** 버튼은 `/api/abstract-quality`로
가는, 제목 + 초록만 보는 빠른 채점 경로입니다. 루브릭 점수만 돌려
주고 journey/similar/저널 앵커링은 빠집니다.

이런 상황에 좋습니다.

- 초록을 계속 고치는 중이고, 도메인 점수가 올랐는지 내려갔는지만
  바로 확인하고 싶을 때.
- 5분에 한 번 초안이 바뀌는데 매번 전체 Q500을 돌리기는 부담일 때.
- "이 초록이 일단 Q1처럼 읽히기는 하나?"를 가장 빠르게 점검하고
  싶을 때.

체감 응답 시간은 12~20초입니다(전체 Q500 forecast는 ~110초).

## 7. Forecast 히스토리 + 초안 자동저장

둘 다 **로컬 전용**입니다. 이 섹션의 어떤 데이터도 서버로 가지
않습니다.

### 초안 자동저장(Draft persistence)

Simulator에서 타이핑하는 동안 입력값이 debounce되어
`localStorage`의 `paperfate.simulator.draft`에 저장됩니다. 5분 안에
탭을 새로고침하면 폼이 다시 채워지고 "draft restored" 알림이 잠깐
뜹니다.

Compare 탭 입력은 `paperfate.compare.draft`에 10분 동안 보관됩니다.
각 폼에 **Clear draft** 버튼이 있습니다.

브라우저가 사생활 보호 모드이거나 저장 용량이 꽉 차 있으면 조용히
저장 실패합니다(앱은 정상 동작). 이 경우엔 새로고침 시 입력값이
사라집니다.

### Forecast 히스토리

Q500 예측이 성공할 때마다 간단한 레코드가 `localStorage`의
`paperfate.forecast.history`에 최대 20건까지 저장됩니다. 각 레코드는
제목, 초록 앞 100자, 핵심 결과 수치, UUID로 구성됩니다.

전체 초록이나 전체 결과는 **서버 측에 저장되지 않습니다**. 이
히스토리는 브라우저 단위입니다. 브라우저를 바꾸면 사라집니다.
현재 단계에서는 URL을 공유해도 받는 쪽 브라우저의 로컬 저장소만
열어 보는 것이라, 진짜 의미의 "다른 기기에서 같은 예측 다시 보기"
공유 링크는 제공되지 않습니다.

## 8. 언어 전환(KO / EN)

헤더 오른쪽 위의 **KO / EN** 토글로 UI 문구(헤더, Simulator, 결과
패널, degraded 배너, Compare 탭)를 한국어/영어로 전환합니다.
예측 자체는 언어 독립적입니다 — LLM은 어차피 입력된 원고 텍스트
그대로(주로 영어)를 읽습니다.

선택값은 같은 브라우저에서는 새로고침 후에도 유지됩니다.

## 9. 개인정보 — 무엇이 서버로 가고, 무엇이 안 가는가

### 서버로 전송되는 것

- 입력한 원고 텍스트: 제목, 초록, 그리고 선택적으로 본문/저자/
  참고문헌 DOI/목표 저널. LLM 채점 레이어(현재 Google Gemini)와
  OpenAlex로 전달되어 처리된 후 폐기됩니다. PaperFate는 원고 본문을
  장기 저장하지 않습니다.
- 예측 1건당 **request ID**(UUID) — 로그 상관 관계용 식별자.
- 익명 **텔레메트리 이벤트**(이벤트 이름 + 식별성 없는 메타 몇 개,
  예: `result_render`, `degraded: true`, `has_journey: true`).
  원고 본문은 절대 포함되지 않습니다. payload는 1KB로 캡됩니다.
  `/api/_telemetry`로 가서 플랫폼 로그에만 떨어집니다.
- **Status 페이지** 프로브는 합성 더미 본문을 보냅니다. 사용자
  원고가 가는 일은 없습니다.

### 서버로 전송되지 **않는** 것

- Simulator와 Compare의 **로컬 초안** — 브라우저 `localStorage`에만
  존재.
- 로컬 **forecast 히스토리** — 위와 동일.
- **언어 선택** — 위와 동일.
- 외부 분석 SDK 데이터 — PaperFate에는 그런 SDK 자체가 없습니다.

### 거부하고 싶다면

클라이언트 텔레메트리는 의도적으로 최소한입니다. 완전히 차단하고
싶다면 일반적인 트래커 차단(uBlock, Brave shields, Firefox 엄격
모드, 사내 DNS 필터 등)으로 `/api/_telemetry` 엔드포인트를
드롭하면 됩니다 — 앱 기능은 그대로 동작합니다. 예측 엔드포인트
자체는 텔레메트리를 호출하지 않습니다.

## 10. 한계 — 결론 내리기 전에 한 번 읽어 주세요

- **룰 폴백은 어디까지나 폴백입니다.** LLM 채점이 실패하면 서버는
  결정론적 룰 기반 예측을 `confidence ≤ 0.30`으로 돌려 줍니다.
  journey/similar 등 다른 카드를 살리기 위해 숫자는 계속 표시되지만,
  항목별 루브릭은 신뢰할 만한 수준이 아닙니다. 호박색 배너가 그
  신호입니다.
- **LLM 채점은 외부 API에 의존합니다.** Gemini 장애나 키 만료가
  있으면 degraded 폴백으로 빠집니다. 응답의 `llm_health` 필드와
  공개 `/api/status` 페이지가 현재 상태를 그대로 보여줍니다.
- **JIF는 모델 추정값이지 신탁이 아닙니다.** 정상 confidence 구간
  안에서도 90% CI는 의도적으로 넓습니다. "Expected JIF"는 최근
  Clarivate JIF 분포에 앵커되어 있고, 저널의 JIF는 매년 모델이
  설명하기 어려운 이유로 흔들립니다.
- **저자 h-index 매칭은 best-effort입니다.** OpenAlex의 검색 1위
  결과를 가져오기 때문에 흔한 성, 로마자 표기 동명이인에서 충돌이
  날 수 있습니다. 입력 strip에서 "0 of N matched"라고 뜬다면 그
  rollup은 노이즈입니다.
- **참고문헌은 한 번에 50건, 저자는 25명으로 캡됩니다.** 긴 논문의
  전체 bibliography는 잘립니다.
- **Journey는 시사적이지 망라적이지 않습니다.** 현실적인 5곳을
  제시할 뿐, 가능한 모든 저널을 보여주지는 않습니다.
- **특정 저널 리뷰어의 판단은 예측하지 않습니다.** Desk-reject 위험은
  모델 수준의 사전 확률이고, 편집자/리뷰어 노이즈는 학습 루프에 들어
  있지 않습니다.

## 11. 자주 묻는 질문(FAQ)

**Q. 내가 입력한 원고가 저장되나요?**
아니요. 텍스트는 LLM 채점(Gemini)과 OpenAlex 해소를 위해 전송된
뒤 폐기됩니다. 서버 측에는 request ID와 식별성 없는 텔레메트리만
남습니다.

**Q. 같은 원고를 다시 돌렸더니 이번엔 호박색 배너가 떴습니다.**
두 실행 사이에 LLM 제공자가 일시적으로 끊긴 것입니다. 몇 분 뒤
다시 시도해 보세요. 보통 짧은 시간 안에 회복됩니다.

**Q. 같은 초록인데 두 번 돌리면 JIF가 다르게 나옵니다. 왜요?**
LLM 채점은 temperature가 0이어도 제공자 측 샘플링/tie-break 때문에
완전한 결정론이 아닙니다. 정직한 숫자는 신뢰구간 쪽에 있습니다.
같은 입력에서 1~2 JIF 정도의 흔들림은 정상입니다.

**Q. Journey 순서대로 그대로 투고해야 하나요?**
강한 shortlist 정도로 보세요. 편집자 핏, 스코프 드리프트, 이전
리젝 경험, OA 강제 여부, 마감 압박 같은 요인은 PaperFate가 보지
못합니다 — 본인의 판단을 위에 얹어야 합니다.

**Q. 도전 저널의 desk-reject 위험이 55%로 나왔어요. 안 좋은 신호인가요?**
NEJM 같은 톱티어 저널에서 강한 원고가 받는 일반적인 수준입니다.
의미 있는 경고는 90% 가까이 갔을 때입니다. 한 가지 입력값 정도로
생각하세요.

**Q. 오프라인에서도 쓸 수 있나요?**
아니요. 예측과 저널 조회는 모두 배포된 API가 필요합니다. PWA
쉘이 UI는 캐시해 두지만, 폼 제출은 서버로 가야 합니다.

**Q. Quick rubric check와 전체 forecast의 차이는?**
Quick rubric check는 제목 + 초록만, 12~20초, 루브릭 점수만 반환합니다.
전체 forecast는 여기에 journey, similar papers, references summary,
author features, target journal anchoring, suggestions, JIF 점추정 +
CI까지 추가합니다. 초록을 계속 고치는 중에는 Quick을, 거의 최종에
가까워졌을 때 전체를 권합니다.

**Q. 비임상 원고에도 쓸 수 있나요?**
모델은 생의학 콘텐츠로 학습되었습니다. 인접 분야(공중보건,
basic/translational, 의료 AI 영상 등)는 잘 동작하고, 생명과학 바깥
원고는 돌아가긴 하지만 루브릭이 그 분야로 튜닝되어 있지 않습니다.

**Q. 한국어 채점 패스가 있나요?**
없습니다. UI는 이중언어지만 루브릭 채점은 LLM이 본 영어 텍스트
기준으로 돕니다. 게재 예정 언어 그대로 제출하세요.

**Q. "request_id"가 뭐고 언제 필요한가요?**
모든 예측 응답에 UUID가 포함됩니다. 특정 실행 결과에 대해 문의할
때 이 UUID를 함께 알려 주시면 플랫폼 로그와 대조해 추적할 수
있습니다. UUID 자체에는 원고 내용이 들어 있지 않습니다.
